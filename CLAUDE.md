# dotgrain — project guide for Claude Code

dotgrain is a React component library where every visual is rendered as **dither** (pixels on/off) or **ASCII** (glyphs). It is distributed as a **shadcn registry** (`npx shadcn@latest add @dotgrain/<name>`), not as an npm package. This repo is both the docs site and the registry.

The full product brief is `docs/dotgrain-brief.md`. Specs and tickets live in GitHub Issues, generated from that brief with `/to-spec` and `/to-tickets`. Work only on the ticket you're given, and don't start work from later phases unless asked. If a decision isn't in the ticket, check the brief before asking.

## Non-negotiable decisions

- **No runtime dependencies in shipped components.** The render engine is raw WebGL2 written in this repo. Do not add three.js, OGL, regl, pixi or any other graphics library. Do not add animation libraries (no Motion/Framer) to registry components; the engine's scheduler handles animation.
- **One engine, thin components.** Every component renders through `<Quantize>` from `registry/engine`. Components never create their own WebGL context.
- **Free vs paid.** This repo is MIT and public. It contains only free components. Paid ("Pro") components will live in a separate private repo and registry (`@dotgrain-pro`). Never add Pro code, tokens or license keys here.
- **Accessibility first.** Real text is real DOM text. Canvases are `aria-hidden="true"`. Effects never replace content.
- **Reduced motion.** `prefers-reduced-motion: reduce` freezes animation but still renders a static frame.

## Stack

- Next.js (latest stable, App Router), React 19, TypeScript strict
- Tailwind CSS v4 for the docs site and component wrappers; components must also work without Tailwind beyond `className` passthrough
- Fumadocs (MDX) for documentation
- pnpm
- Vitest for unit tests, Playwright for visual regression screenshots
- shadcn CLI for building the registry (`shadcn build`)

## Repo layout

```
dotgrain/
  app/                        # Next.js docs site (routes, layouts)
  components/site/            # site-only UI (nav, preview frame, knobs panel, code tabs)
  content/docs/               # MDX docs pages
    components/<name>.mdx
  registry/
    engine/                   # registry item: @dotgrain/engine (registry:lib)
      context.ts              # shared WebGL2 context manager
      scheduler.ts            # single rAF loop, visibility + reduced motion
      programs.ts             # shader sources as TS strings, program cache
      patterns.ts             # Bayer matrices, blue-noise texture
      palettes.ts             # named palettes + parsing
      glyphs.ts               # glyph ramps + glyph atlas builder
      fields.ts               # built-in value fields (GLSL + JS twins)
      cpu.ts                  # Canvas2D fallback renderer
      diffusion.ts            # Floyd–Steinberg / Atkinson (CPU, still images)
      provider.tsx            # <DitherProvider>, useDitherTokens()
      quantize.tsx            # <Quantize> React component
      types.ts
      index.ts
    ui/                       # one file per component (registry:ui)
    examples/                 # demo files rendered in docs previews
  public/r/                   # GENERATED by `pnpm registry:build` — never edit
  registry.json
  components.json
  LICENSE                     # MIT
```

## Commands

- `pnpm dev` — docs site at localhost:3000
- `pnpm registry:build` — runs `shadcn build`, writes `public/r/*.json`
- `pnpm test` — Vitest
- `pnpm test:visual` — Playwright screenshots of every example in every palette
- `pnpm lint` / `pnpm typecheck`

Run `pnpm typecheck && pnpm test && pnpm registry:build` before calling any task done.

## Registry conventions

- Every component is one registry item, type `registry:ui`, with `"registryDependencies": ["@dotgrain/engine"]`.
- `@dotgrain/engine` is type `registry:lib`. Its files install to the user's `lib/dotgrain/` folder.
- `dependencies` in registry items should be empty. If a component truly needs an npm package, stop and ask.
- Fill `title`, `description` (one plain sentence; it feeds search, llms.txt and the copy prompt), `categories`, and `meta: { "modes": ["dither" | "ascii"] }`.
- File names are kebab-case (`dither-image.tsx`); exports are PascalCase (`DitherImage`).
- Every component file starts with `"use client";`.

## Code conventions

- TypeScript strict, no `any` in public types. Export a `<Name>Props` type for each component.
- Props: token props (`mode`, `pattern`, `cell`, `palette`, `glyphs`, `speed`, `contrast`, `threshold`) are always optional and fall back to the provider.
- Forward `className` and `style` to the outer element. Accept `ref` (React 19).
- No global CSS from components. No `@keyframes` injection.
- Keep each component under ~150 lines; logic belongs in the engine.
- Comments only where intent is non-obvious (shader math, scheduling).

## Performance budgets

- Engine: under 15 kB min+gzip.
- Each component: under 3 kB min+gzip on top of the engine.
- Render at quantized resolution (element size ÷ cell), then upscale with `imageSmoothingEnabled = false`.
- Cap device pixel ratio at 2. Pause anything offscreen or in a hidden tab.

## Definition of done (every task)

- Typechecks, tests pass, registry builds.
- New component has: registry entry, example file, MDX page with props table, a visual regression screenshot.
- Works in a fresh `create-next-app` project via `npx shadcn@latest add http://localhost:3000/r/<name>.json`.
- Reduced motion and WebGL-unavailable paths verified.
